# ПЕДАГОГ

Авторская деловая игра Виктории Геннадьевны Науменко.

**Сайт:** https://0011nvg.github.io/pedagog/

Реальные ситуации. Разные роли. Новые решения. Участники разбирают узнаваемые школьные ситуации: сначала их видят две-три роли, затем ведущий открывает три обстоятельства, и с каждым в разговор входят новые участники — одноклассник, классный руководитель, родитель, психолог, администрация. Участники учатся слышать позиции, отделять факты от первого впечатления и вместе находить решение.

## Содержание

- 40 ситуаций в 9 темах, в каждой 5–6 ролей (220 ролей, 120 обстоятельств) — `src/deck.js`, единый источник для онлайн-игры, каталога и печати. У каждой ситуации — 3 возможных подхода к решению с последствиями (`options`), профессиональные выводы (`takeaways`) и рамка решения (`note`: что обязательно по закону и не является предметом выбора).
- Допустимые роли: ученик, одноклассник, учитель-предметник, классный руководитель, родитель, педагог-психолог, социальный педагог, заместитель директора, директор, советник директора по воспитанию, школьный медиатор. Наблюдатель — функция свободных участников.
- 15 карточек ресурсов (инструменты для поиска решения) и 10 вопросов рефлексии.

## Ход раунда

Исходная ситуация → первые позиции → обстоятельство 1 → 2 → 3 (с каждым входят новые роли) → поиск решения → рефлексия. Форматы 15, 40 и 90 минут задаются в `platform/engine.js` (`FORMATS`); в 15 минутах обстоятельства 2 и 3 открываются вместе, 90 минут — два раунда, перерыв и итог. Регламент на сайте, в правилах и в печатной инструкции строится из одного места.

Игроков не обязательно столько, сколько ролей: первые роли — разным участникам, поздние — по кругу (ведущий может переназначить), есть режимы «сцена», «совет коллег» и «один участник». 13–40 участников делятся на команды по 4–6.

## Онлайн-игра

Один экран ведущего; кнопка «Экран для всех» убирает управление. Скрытые обстоятельства и роли не показываются до своего этапа. Состояние — в localStorage (`pedagog-platform-session-v5`), после перезагрузки встреча открывается на том же этапе с таймером на паузе. На этапе «Поиск решения» ведущий видит рамку решения и свёрнутую подсказку с возможными подходами, на рефлексии — профессиональные выводы (на «экране для всех» подсказки скрыты). Итоги: .txt или печать. Сетевых комнат нет — это честное ограничение статического хостинга.

## Печать

Конструктор `print.html` открывается кодом автора. Код нигде не хранится: `print-pack.js` содержит контрольный пакет, зашифрованный ключом из кода (PBKDF2-SHA256 + AES-GCM), и конструктор открывается, только если код его расшифровывает. Сменить код: `node scripts/set-author-code.cjs` (ввод скрыт, дважды), проверить: `node scripts/set-author-code.cjs --check`; затем `npm run build`, commit, push. Это барьер для интерфейса печати на статическом хостинге, а не серверная защита.

Для каждой ситуации — комплект двусторонних карточек 99 × 140 мм, 4 на листе A4: ситуация, роли (на рубашке — когда роль входит), три обстоятельства («не открывать до сигнала»), две карточки ведущего (ход игры и распределение ролей; возможные подходы к решению, выводы и рамка решения), рефлексия, наблюдатель. Переворот по длинному или короткому краю, пробный лист, сдвиг оборота, экономная печать, листы ведущего A4.

`npm run print:pdf` собирает те же карточки в PDF (Playwright + Chromium) в игнорируемую папку `qa/print/` и проверяет, что текст помещается в карточки. Открыто PDF не публикуются.

## Разработка и проверки

Node.js 18+, внешние пакеты для сборки и тестов не нужны.

```sh
npm run build        # страницы в корне для GitHub Pages + qa-preview/
npm test             # реестр, движок, печатная раскладка, страницы и ссылки
npm run check:browser  # проход онлайн-игры в Chromium (нужен Playwright и локальный сервер на :8765)
npm run print:pdf    # PDF-комплекты в qa/print/
```

Источники: `src/deck.js` (данные), `platform/engine.js` (ход игры), `platform/session.js` (онлайн-интерфейс), `platform/catalog.js` (каталог и справочник), `platform/print-layout.js` + `platform/print.css` (печать), `platform/art.js` (графика), `platform/pages/*.html` (содержательные страницы), `platform/style.css` (дизайн-система). Сгенерированные HTML в корне вручную не правятся — GitHub Actions проверяет их соответствие исходникам.

Шрифты Montserrat и Onest хранятся в `platform/fonts/` (SIL Open Font License 1.1), внешних запросов сайт не делает.

## Границы проверки

Программные, браузерные и визуальные проверки PDF не заменяют реальные педагогические испытания и физическую двустороннюю печать (сначала — пробный лист в масштабе 100 %). Эффективность обучения не заявляется. Отчёт о последней проверке — `docs/RELEASE-FINAL-2026-10-30.md`.
