## Пользовательские маршруты

Главная → выбор онлайн или настольного формата. Каталог → полный паспорт → запуск выбранного кейса или подготовка печати. Правила → методический кабинет → сценарий встречи. Онлайн: настройка → договорённости → ситуация/позиции → первая попытка → наблюдение → ресурс → повтор → проверка последствий → решение → рефлексия → завершение. Данные команд и раундов независимы.

## Совместная работа с разных устройств: спроектирована, не подключена

Текущая реализация: одно устройство ведущего, несколько команд/столов и ручной перенос проверенного JSON. Кода комнаты и ложной синхронизации нет.

Для следующего серверного этапа предлагается отдельный HTTPS API и PostgreSQL с транзакционным номером версии:

- `rooms`: случайный непрогнозируемый внутренний ID, хеш приглашения, ведущий, статус, версия и время удаления.
- `members`: псевдоним, роль доступа (host/participant), команда, отдельный сессионный токен с ограниченным сроком.
- `rounds` и `team_states`: кейс, назначения, ресурс, поворот, общие согласованные записи.
- `events`: минимальный журнал изменений с версией, без личных признаний и скрытых персональных данных.
- Создание комнаты и приглашений — только ведущим; короткий код дополнен ограничением попыток, сроком жизни и отдельным токеном участника.
- `POST /rooms`, `POST /rooms/join`, `GET /rooms/:id/state`, `PATCH /rooms/:id/state` с ожидаемой версией, `DELETE /rooms/:id`.
- Обновления через SSE/WebSocket; при разрыве — повторная загрузка последней версии. Конфликт записи возвращает 409, клиент не перезаписывает чужую правку молча.
- Сервер проверяет составы, роли, ресурсы, права на команды и переходы. Клиентское скрытие элементов не является авторизацией.
- Общие записи и личные роли возвращаются по разрешениям; хост может завершить комнату и отозвать приглашение. Срок хранения выбирается до запуска, затем записи удаляются по политике.

Для реализации нужны выбранный владельцем сервер/БД, домен API, политика хранения и сервисные секреты. Их нет в текущем GitHub Pages проекте. Никакие внешние аккаунты не созданы, секреты не добавлены. План не считается работающей мультиплеерной функцией.

## Печать и прежние коммерческие условия

Существующий зашифрованный print-pack.js сохранён. Код не известен разработчику этого изменения, не перебирается и не сохраняется. Новая компоновка доступна после успешной расшифровки прежнего пакета. Готовые прежние PDF остаются отдельной редакцией; актуальный набор формируется из общего реестра через диалог «Печать → Сохранить как PDF». Автономные проверочные PDF не публикуются открыто.

Общий код — прежняя модель доступа, не персональная лицензия или защита публичных текстов каталога от копирования. Платёжная система не имитируется.

## Порядок выпуска

`npm run build` → `npm test` → браузерные проверки → контроль PDF → отдельный коммит/PR → проверка GitHub Actions → объединение → контроль опубликованных страниц. QA-артефакты и открытые PDF исключены из Git.
